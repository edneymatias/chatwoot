# Phase 10: Sync Script Update for Ciclo 2 Core-File Touches

**Status**: designed — ready for implementation
**Depends on**: Phases 5-9 (ciclo 2, as actually implemented)

## Background

`bin/sync-custom-module-hooks` (built in Phase 4) applies an anchor-based,
idempotent, fail-fast `MANIFEST` of inserts to core Chatwoot files, so the
custom Kanban module can be wired into a checkout without hand-editing.
Ciclo 2 introduced new core-file touches that were never added to that
manifest — this phase audits everything that actually diverged and closes
the gap.

## Audit mechanism

Extend `bin/sync-custom-module-hooks` with a new `--audit [BASE_REF]` mode
(default `BASE_REF`: merge-base of the working branch and `develop`, today
`9d769dfcd`). It:

1. Runs `git diff --name-status BASE_REF...HEAD` (plus working tree) and
   keeps only `M` (modified) paths — new files aren't core touches.
2. Drops paths matching the permanent exclusion rules below.
3. Cross-references what's left against the `file:` entries already in
   `MANIFEST` and prints two buckets: **covered** (already has an entry)
   and **gap** (modified, no entry — needs review).

This is reusable every future cycle, not a one-off report, which is the
actual fix for "changes accumulate untracked."

### Permanent exclusions (never flagged as a gap)

- `db/schema.rb` — regenerated by `rails db:migrate`; the migration files
  themselves live under `db/migrate/*.rb` as ordinary new files and need
  no anchor.
- `spec/**`, `specs/**`, `docs/**`, `*_spec.rb`, `*.spec.js`, `*.md` —
  tests and documentation, not wiring.
- i18n locales other than `en/` — translation is Crowdin-managed per
  project convention, not part of the custom module.
- Annotate-gem schema-comment churn (e.g. `app/models/category.rb`,
  `message.rb`, `platform_banner.rb`, `channel/whatsapp.rb`, and the
  `enterprise/app/models/*` annotate blocks) — auto-regenerated by
  `bundle exec annotate` whenever any model's table changes, unrelated to
  Kanban. Excluded by path/content heuristic, not manually maintained.

### Out of scope (local/fork environment, not module wiring)

`docker-compose.yaml`, `.gitignore`, `AGENTS.md` — legitimate local dev
environment and tooling changes (fixed Postgres/Redis volume mounts,
tokensave/headroom entries, container-first startup instructions for
LLM agents), but not part of what makes the Kanban module functionally
present in a checkout. Left out of the manifest entirely. If the patch
package extraction (see ciclo 3 phase 13 preview) happens, this concern
naturally goes away since these files would no longer need to travel with
the patch at all.

## Audit findings (2026-08-03, HEAD `7e666f57c`, base `9d769dfcd`)

### Gaps — new MANIFEST entries needed

| File | Touch |
|---|---|
| `config/application.rb` | `eager_load_paths` additions for `custom/lib` and `custom/app/**` — foundational, nothing in `custom/` loads without this |
| `config/routes.rb` | `resources :pipeline_stages` (+ nested `required_fields`) and `resources :opportunities` |
| `config/features.yml` | `opportunities` feature flag entry |
| `app/services/automation_rules/action_service.rb` | `AutomationRules::ActionService.prepend_mod_with('AutomationRules::ActionService')` — wires the `create_opportunity` automation action (Phase 2) |
| `app/javascript/dashboard/i18n/locale/en/settings.json` | new keys for the automation builder |
| `app/javascript/dashboard/i18n/locale/en/automation.json` | new keys for the automation builder |
| `app/javascript/dashboard/helper/automationHelper.js` | support for the `create_opportunity` action in the rule builder |
| `app/javascript/dashboard/composables/useAutomationValues.js` | support for the `create_opportunity` action in the rule builder |

`settings.json`/`automation.json` are inserts into existing JSON objects
(not a new-file import like `opportunities.json`), so their manifest
entries need a comma-safe anchor/insert, same mechanism, just written
carefully.

### Already covered (no action)

`app/javascript/dashboard/helper/actionCable.js`,
`app/javascript/dashboard/routes/dashboard/dashboard.routes.js`,
`app/javascript/dashboard/components-next/sidebar/Sidebar.vue`,
`app/javascript/dashboard/routes/dashboard/settings/settings.routes.js`,
`app/javascript/dashboard/store/index.js`,
`app/javascript/dashboard/featureFlags.js`,
`app/javascript/dashboard/i18n/locale/en/index.js`.

## Implementation notes for speckit

- Add `--audit` mode to `bin/sync-custom-module-hooks` per the mechanism
  above, including the exclusion rules as data (patterns), not hardcoded
  branching, so they're easy to extend next cycle.
- Add the 8 gap entries above to `MANIFEST`, matching the existing
  anchor/insert style (see Phase 4 entries in the same file for JSON
  comma handling precedent, if any, otherwise establish it here).
- Run `bin/sync-custom-module-hooks --check` after the manifest update to
  confirm all entries (old and new) resolve against the current tree.
- Run the new `--audit` mode against `9d769dfcd...HEAD` as an acceptance
  check: it should report zero gaps once the manifest update lands.
